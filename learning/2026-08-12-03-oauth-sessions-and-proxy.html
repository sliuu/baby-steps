Sign In

Google and GitHub authentication, a session that survives a refresh, and a file that runs before every request in the app.

The whole step in five lines

  1. You never give Baby Steps your Google password. Google vouches for you instead.
  2. Signing in ends with two tokens in cookies your JavaScript cannot read.
  3. proxy.ts runs before every request, refreshes those tokens, and bounces strangers to /login.
  4. Supabase is the OAuth client — that's why Google shows a supabase.co address.
  5. The placeholder avatar is now a real menu with your name and a sign-out button.
Read this before anything else

middleware.ts does not exist in Next.js 16. It was renamed to proxy.ts, and the exported function must be called proxy too. Every tutorial you find online will say middleware, because the rename is new.

ProjectPlan.md said middleware.ts as well — written before we checked. It's corrected now. This is exactly why AGENTS.md says to read the docs bundled inside node_modules/next/dist/docs/ rather than trusting memory.

2 · Tools — and every word I use

Nothing here is defined later than it's used.

Auth words

OAuthA protocol for "let someone else vouch for who I am." You prove yourself to Google; Google tells us the result. We never see your password.
providerThe one doing the vouching. Google or GitHub here.
OAuth clientThe app registered with the provider. Counter-intuitively this is Supabase, not Baby Steps.
authorization codeA short-lived one-time voucher in the URL after you approve. Not a session. It gets swapped for one.
access tokenThe thing that actually proves you're signed in. Expires after about an hour.
refresh tokenLonger-lived. Used to get a new access token without making you sign in again.

Browser and web words

cookieA small value the browser stores per site and re-sends on every request to it. How the server remembers you between page loads.
httpOnlyA flag saying "JavaScript may not read this cookie." Only the browser and server see it. Blocks a whole class of token theft.
redirectA response that says "go here instead." Status 307 is the one we return.
GET vs POSTGET fetches and can be triggered by a link or an image. POST submits and cannot be triggered accidentally. Sign-out must be POST.
environment variableConfig passed in from outside the code, so the same source runs locally and in production with different values.

Next.js words

proxyCode that runs before every matching request. Called middleware until Next 16. Runs on Node.js; the Edge runtime is not supported and cannot be configured.
Route HandlerA route.ts exporting GET/POST. An HTTP endpoint rather than a page — it returns data or a redirect, not HTML.
Server ActionA function marked "use server" that you can hand straight to a form's action. Next handles the network round-trip.
dynamic routeMarked ƒ in the build output. Rendered per request because it reads cookies. Opposite of ○ static.

3 · What this changes for you

Three things that affect what you build. Everything else is plumbing, and it's in the box at the end.

1 · Google shows a supabase.co address, and that's not a bug

Google doesn't redirect back to Baby Steps. It redirects to Supabase, which redirects to us.

1 · you
click Continue with Google
→
2 · google
you sign in and approve
→
3 · supabase
/auth/v1/callback gets the code
→
4 · baby steps
/auth/callback swaps it for tokens

Supabase is the app registered with Google, so Google shows Supabase's address on the consent screen. Only a paid custom domain changes it. GitHub is fine already — it shows the app's name instead of the host. If someone flags the consent screen in review, that's the answer.

2 · The browser can't tell whether you're signed in — only the server can

The session token lives in an httpOnly cookie, which JavaScript cannot read. Deliberate: an XSS bug still can't steal it.

What follows from that, for the UI:

  • Auth branches happen in Server Components. There's no client-side isLoggedIn to read.
  • No signed-out flash and no auth spinner — the server knows before the first byte of HTML.
  • Any component that needs the user takes it as a prop. That's why user is threaded down through AppShell to TopNav rather than fetched where it's used.

3 · The redirect is cosmetic. Don't hide anything behind it

proxy.ts bounces signed-out visitors to /login. It's a pre-filter, not a lock — the Next.js docs say so outright, which is why app/page.tsx checks again, and why Step 4 puts the real guarantee in the database.

Design consequence: a redirect is fine for routing, never for secrecy. If a panel shouldn't be seen, it must not be rendered — not merely navigated away from.

The one thing the proxy is genuinely for

Tokens expire hourly, and only the proxy runs early enough to write a fresh one back. Delete the file and everyone gets logged out mid-session, at random. That's its real job; the redirect is a side benefit.

The plumbing, one line each

You don't need to hold these. They're here so the code doesn't look arbitrary.

4 · Code

Five snippets. One line of why under each — skim the code, read the line only if the code looks odd.

components/UserMenu.tsx — asChild

The one pattern here you'll reuse in every step from now on.

<form action={signOut}>
  <DropdownMenuItem asChild>
    <button type="submit" className="w-full cursor-pointer">Sign out</button>
  </DropdownMenuItem>
</form>

asChild tells a Radix component: don't render your own element — put your behaviour and styling on my child instead. So the menu item's keyboard handling and focus states land on a real <button> that a form can submit.

It's Radix's answer to "I need your behaviour but my markup," and it's how you'll wrap links, buttons, and triggers for the rest of the project without nesting two interactive elements.

lib/supabase/env.ts — the one that would have bitten you

const url = process.env.NEXT_PUBLIC_SUPABASE_URL;
const anonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;

Written out literally on purpose. Next find-and-replaces the exact text process.env.NEXT_PUBLIC_… at build time, so a tidy read("NEXT_PUBLIC_SUPABASE_URL") helper compiles, typechecks, works on the server, and is undefined in the browser. Same shape as Tailwind's class scanning in Step 2: the tool reads text, it doesn't run your code.

The key is public by design — it grants the anon role and RLS decides the rest. service_role must never take this prefix.

lib/supabase/server.ts — cookies() is async now

const cookieStore = await cookies();   // ← a promise in Next 16

Plain object in Next 14, promise-with-a-warning in 15, promise only in 16. Same for headers(), params, and searchParams — so any component touching them is async.

proxy.ts — three lines that are easy to get wrong

setAll(cookiesToSet, headers) {   // ← two args in @supabase/ssr 0.12
  …
  request.cookies.set(name, value);    // ← request too, not just response
  …
}

return response;   // ← the one setAll rebuilt, not a fresh NextResponse.next()

The second setAll argument carries Cache-Control and friends, which stop a CDN serving one person's session to the next. Returning a fresh response instead of the rebuilt one silently drops the refreshed cookie — the classic "it logs me out every hour" bug.

app/auth/callback/route.ts — two lines of security

const nextParam = searchParams.get("next") ?? "/";
const next = nextParam.startsWith("/") ? nextParam : "/";

Relative paths only. Without it, /auth/callback?next=https://evil.example signs you in and then hands you, freshly authenticated, to someone else's site.

5 · The shadcn before/after

Two new components this step: avatar and dropdown-menu.

The standing habit is to show a new shadcn component as the CLI delivers it, then after our tokens reach it. This time the interesting part is that we changed nothing.

Here's what the CLI wrote into dropdown-menu.tsx:

className={cn(
  "bg-popover text-popover-foreground …",
  "focus:bg-accent focus:text-accent-foreground …",
  className
)}

Those are token names, not colours. And Step 1 already pointed those tokens at our palette: 

--popover:            var(--surface);   /* #fdfcf8 warm off-white */
--popover-foreground: var(--ink);       /* #1c1a17 warm near-black */
--accent:             #ece7dc;          /* the stone pill from the nav */
--radius:             0.625rem;
Stock shadcnOurs, no edits
Menu groundPure white #fffWarm off-white #fdfcf8
TextNear-black, geometric sansWarm near-black, EB Garamond
HoverCool greyThe same stone as the nav pill
Dark modeCool slateOur warm dark, automatically

That's the whole argument for the token layer. Two components arrived, read the variables already on the page, and matched a design they've never heard of. The only thing we wrote by hand was the fallback initial's font-heading.

One real edit, for a real reason

The avatar fallback uses Intl.Segmenter to take the first character of your name, not name[0]. A name starting with an emoji or an accented character is several code units, and slicing one of them renders a broken glyph. Step 10 needs the same trick for sticker marks, so it's worth meeting now.

6 · Verifying it

The guard can be checked without a browser:

$ curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://localhost:3000/
307 http://localhost:3000/login

$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/login
200

And the build shows the shape of the app changing:

Route (app)
┌ ƒ /                        ← was ○ static in Step 2
├ ○ /_not-found
├ ƒ /auth/auth-code-error
├ ƒ /auth/callback
└ ○ /login

ƒ Proxy (Middleware)

/ moved from ○ to ƒ. It reads cookies now, so it can't be built ahead of time — there's no single correct HTML for a page that differs per visitor. /login is identical for everyone, so it stays static.

By hand

  • Visit / signed out — you land on /login.
  • Sign in with Google, then with GitHub. Both should return you to the calendar.
  • Refresh — you stay signed in. That's the cookie doing its job.
  • Open the avatar menu. ↓ ↑ move, Esc closes, focus returns to the avatar. None of that is our code — it's Radix.
  • Sign out — back to /login, and / is blocked again.
Known, accepted

Google's consent screen shows your Supabase project address rather than "Baby Steps," because Supabase is the registered OAuth client. Fixing it needs a paid custom domain. GitHub already shows the right name, since it displays the OAuth app's name instead of the callback host. Revisit at Step 17.
